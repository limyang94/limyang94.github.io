00

一页速览用 2 分钟建立整体认知

时长判断不是“自动判卷”，而是把“答得明显比同类快”的答卷挑出来，给审核员一个优先级信号。

目标
识别过快、疑似乱答
只看答题快慢，不看答案内容对错；辅助审核，不替代人工判断。
方法
两步判断
第一步清洗单题超长；第二步把整卷时长与同类分布比较。
结果
四态 + 三态闸门
待定 / 过快 / 正常 / 过慢；审核闸门只使用前三种语义，过慢按正常处理。
参照
逐级回退
问卷×车系 → 问卷 → 类型 → 品牌 → 种子值 → 待定。
规则版本
两套并存
normal_v1（默认）与 percentile_v2（经验分位）；可配置切换、可回滚。
时延
T+1 跑批
数据组 T+1 推事件流；今天提交的卷，最快明天跑批后才有结论。
稳定性
判定冻结
判定结果冻结不回算；调参只影响未来；待定卷每周重判。
入口
三处可见
审核列表/详情、答题时长统计报表、分位门槛配置。
PM 必记 6 句话
  1. “异常”是可疑信号，不是定性结论。时长异常只说明“比同类快”，不代表答案一定有问题。
  2. “待定”不是“正常”。待定表示数据未就绪或参照不足，系统没有下结论。
  3. “过慢”只提示，不入闸门。当前只有“过快”会影响系统初判。
  4. 报表门槛是“当前值”，审核记录里的门槛是“冻结值”。两者不能直接对比。
  5. 调 P_TI / P_JUAN 只影响未来。已冻结的判定不会回算，历史审核结论不受影响。
  6. 多车系问卷，判定只取第一个车系。配置车系时把最具代表性的放第一位。
01

定位与边界它解决什么、不解决什么

积分答题环节中，部分用户为了薅积分，会飞快乱点提交。单看一份卷很难判断，但放到“同品牌/同车系/同类型”的样本里比较， 异常短的卷就会凸显。时长判断就是替审核员做这个比较。

它解决
把“最值得怀疑的卷”排到前面
统一口径、自动计算异常阈值、单题超长清洗、冷启动逐级回退、提供审核列表红标与统计报表， 减少逐份人工估时。
它不解决
不判断答案内容对错
不抓“慢慢乱答”，不自动决定积分发不发，不做实时判定，也不做跨品牌/跨车型的精细对比（当前最细到车系）。

与其他报表的关系

时长判断不进入业务报表（客户表 / 问题表）的取数口径。业务报表的“是否最终版、是否无效”等字段与时长无关； 时长只影响两个地方：积分审核列表/详情，以及答题时长统计报表。

数据时延 时长数据不是实时的。前端埋点 → 数据组 T+1 推送 → 系统凌晨跑批 → 审核列表/报表更新。 今天提交的卷，最快明天跑批后才有结论；数据组延迟则顺延。这是正常时延，不是故障。

关键名词看懂后面所有规则的基础

名词通俗解释备注
事件流用户在问卷里的每一次打开页面、修改答案，按时间记录成一条事件。数据组 T+1 推送，系统只读。
单题原始时长
x_q		用户在某一道题上实际停留的时间；同一题多次修改会累加。单位秒；是训练阈值的唯一原始来源。
单题有效时长
x_q*		对超长单题做清洗后的时长，保留在单题明细中。清洗规则见第 06 节；当前 normal_v1 判定使用原始总和，percentile_v2 使用截尾后的推定池。
推定答卷时长
y		用于判定的整卷用时：percentile_v2 为各题截尾后相加；normal_v1 当前为原始单题时长相加。不是用户从打开到提交的墙钟时间。
T95 / T05同一组样本的经验分位阈值：T95 是 95 分位，T05 是 5 分位。percentile_v2 使用；不假设数据服从正态分布。
有效答题时长
x 门槛		单题的“超长线”。超过它，单题会被截尾或折算，避免拉高整卷。报表里通常用 ≤ 展示为“单题应不超过”。
有效答卷时长
y 门槛		整卷的“过快线”。低于它，整卷会被标记为过快可疑。报表里通常用 ≥ 展示为“整卷应不低于”。
参照层级
duration_ref_level		判这份卷时，用的是哪一层统计分布：问卷层/车系层/类型层/品牌层/种子值等。层级越细，结论通常越可信。
基线状态
baseline_status		该组样本处于什么阶段：未初始化/采集期/预热期/稳定期。稳定期阈值可直接采信；采集期结论应视为待定。
分位快照
duration_p_juan / p_ti		冻结判定时，记录当时生效的两个分位配置值。供历史追溯，避免调参后无法解释旧结论。
规则版本
RULE_VERSION		当前系统使用哪套判定规则：normal_v1 或 percentile_v2。线上以配置页返回值为准。
冻结判定结论在评估时写入审核记录，之后不再自动重算。调参、样本增长都不改历史结论。
样本量 n参与某一组统计的样本数量。题目级按“单题时长”计，答卷级按“整卷”计。n 越大，阈值越稳定。
统计窗口基线只统计最近一段时间的样本。当前基线跑批窗口为 180 天；类型层为近 90 天。窗口内样本不足会回退到更粗的层级。
单位说明 数据库存储的时长统一是秒；统计报表 KPI 的 μ/σ/门槛也是秒； 审核列表页面和 CSV 导出里的“答题时长（分）”“时长下限（分）”按分钟展示，保留 1 位小数。

四类数据池：为什么要分开

数据池内容用途是否回灌训练
原始基线池 answer_question_duration.x_q（原始单题时长） 训练题目 T95、答卷 T05 是，唯一来源
推定池 duration_answer_metric.y = Σ min(x_q, T95) 判定用的整卷 y；T05 的样本池 否
展示池 stat_* 的 Welford 矩（n / μ / M2，采样原始 x_q） 答题时长统计报表展示 否
有效值 x_q*、y（截尾/折算后的值） 明细展示、判定输入 否
关键约束 补偿/截尾后的值绝不回灌原始基线池。否则会出现“μ 越低 → 补偿越低 → μ 更低”的自锁， 阈值会系统性失真。这也是为什么报表采样只读原始 x_q，不读 x_q*。
05

两套规则版本先确认线上到底用哪套

系统同时保留两套判定规则，由配置 RULE_VERSION 选择。默认 normal_v1； 切到 percentile_v2 需要基线表已就绪，否则判定层会自动回落 normal_v1，避免全量待定。

维度normal_v1（默认 / 回滚位）percentile_v2（经验百分位 / 目标方案）
定位v211 既有实现，正态假设，保留旧语义（样本不足=正常放行）V1.1 目标方案，不假设分布形状
单题超长处理会计算 x_q*：超过 μ题 + k题·σ题 的题折算为 μ题 / 3，写入明细；当前判定取原始 Σx_q超过该题 T95 的题，截尾为 T95；判定取截尾后的推定池 y
整卷阈值y门槛 = μ卷 + k卷·σ卷低门槛 T05（过快）+ 高门槛 T95（过慢提示）
过快判定y ≤ y门槛，且门槛 > 0y ≤ T05
过慢判定不支持y ≥ T95，只提示，不入闸门
样本不足正常放行（旧语义）待定，禁止默认正常
样本门槛问卷/车系/类型 2000；品牌 300问卷/车系/类型 200，预热 50；品牌 300，预热 50
适用阶段过渡期、回滚、旧数据解释基线稳定后的目标规则
切换方式修改 duration_threshold_config 中 RULE_VERSION 一行；回滚改回即可
为什么 normal_v1 会“检不出过快” 答题时长是典型的右偏长尾数据：大量短时长 + 少量超长。极少数超长记录会把 σ 拉得比 μ 还大， 使 μ卷 + k卷·σ卷 变成负数。旧规则又要求“门槛 > 0”才判异常， 于是负门槛时过快检测整体静默失效。v2.2.4 前端文档里的 y_threshold = -374 就是实测证据。 percentile_v2 改用经验分位，不依赖 μ/σ 的分布假设，因此更稳。
06

第一步：单题清洗先处理“某一题停了很久”的干扰

用户可能中途接电话、离开页面，导致某一道题特别长。如果直接求和，整卷时长会被这一道题“撑”得很正常， 乱答卷反而被掩护。所以先做单题层清洗，再求整卷用时。

单题原始时长怎么来

x_q = 用户在该题上所有停留间隔之和 事件流按时间升序；首题以“开始答题”事件为锚点；同一题多次修改会累加；负间隔按 0 处理；冷启动/基线不可用时，单题做 600 秒硬上限保护。

两种清洗规则

场景normal_v1percentile_v2
正常单题 保留 x_q 保留 x_q
超长单题 x_q ≥ x门槛 → 替换为 μ题 / 3 x_q > T95 → 截尾为 T95（等于 T95 不算超长）
基线不足 门槛 ≤ 0 → 不做替换，保留原值 T95 不可用 → x_q* = x_q，只做 600 秒硬上限
极端脏数据 冷启动/门槛不可用时，最高 600 秒；有门槛时按超时规则处理 基线未就绪时最高 600 秒；基线就绪时按 T95 截尾

x门槛在 normal_v1 下由 P_TI 分位计算；T95 在 percentile_v2 下同样由 P_TI 分位决定，默认 95%。

当前代码的重要口径 normal_v1 的单题清洗值 x_q* 仍会写入明细，但当前判定实际使用原始 Σx_q， 不是 Σx_q*。因此 μ/3 折算目前主要保留在明细层，不直接改变 normal_v1 的判定结果。 percentile_v2 则使用与基线同源的 Σmin(x_q, T95)。 旧版业务手册写的是 Σx_q*，以当前代码口径为准；如业务要求 normal_v1 也按清洗后的 y 判定，需要开发确认/改造。
normal_v1 与 percentile_v2 的单题统计口径也不同 normal_v1 的“单题 μ/σ”来自问卷层汇总的单题时长（同问卷所有题汇总成一个分布），不是逐题统计； percentile_v2 的题目 T95 是逐题计算的。因此两套规则的“单题超长线”不可直接横向比较。
为什么历史上用 μ/3，percentile_v2 改用 T95 μ/3 是 v211 的设计，会把超长题压到一个很低的固定值，容易系统性低估整卷时长；而且一旦补偿值回灌样本池，会形成自锁。 T95 截尾更稳定、可解释，也不会把异常值压到极端低值。因此 percentile_v2 改为“超过 95 分位就截到 95 分位”。 当前 normal_v1 判定改用原始 Σx_q 后，μ/3 主要保留在明细层。
报表采样口径 答题时长统计报表的 stat_* 采样的是原始 x_q，不是清洗后的 x_q*。 因此报表里的 μ/σ 反映真实原始时长，不会因为“补偿值”而越来越低。
07

第二步：整卷判定把整卷用时和同类样本比，得出四态

按当前规则把各题时长合成整卷用时 y；再用同组的统计阈值比较， 输出“待定 / 过快 / 正常 / 过慢”。注意：两套规则的 y 口径不同，不能直接混用。

normal_v1
正态假设版
y = Σ x_q（原始总和；x_q* 仅保留在明细）
y门槛 = μ卷 + k卷 · σ卷
k卷 = Φ⁻¹(P_JUAN / 100)，默认 P_JUAN=5 → ≈ -1.6449
判定：y ≤ y门槛 且 y门槛 > 0 → 过快；参照不足 → 正常放行；无明细 → 待定。 不输出过慢。
percentile_v2
经验百分位版
y = Σ min(x_q, T95)（推定池）
T05 = 同组 P05（默认 5%）
T95 = 同组 P95（默认 95% = 1 − P_JUAN）
判定：y ≤ T05 → 过快；y ≥ T95 → 过慢； 介于两者 → 正常；T05 不可用 → 待定。

四态结果与审核闸门

待定
duration_status=0 / is_duration_anomaly=0
数据未就绪或参照不足，系统没有下结论。审核闸门保持待定，次日继续看。
过快
duration_status=1 / is_duration_anomaly=1
整卷用时 ≤ 过快线，疑似乱答。审核闸门会判“无效”（在 NPS/NSS 未命中后）。
正常
duration_status=2 / is_duration_anomaly=2
整卷用时在正常区间。审核闸门会判“有效”（前提是 NPS/NSS 也未命中）。
过慢
duration_status=3 / is_duration_anomaly=2
整卷用时 ≥ 过慢线，仅作提示。审核闸门仍按“正常”处理，不影响系统初判。
判定四态闸门三态审核闸门动作页面提示
待定0 待定0 待定保持待定，次日重新检查灰 / 不高亮
过快1 过快1 异常系统初判“无效”红色高亮
正常2 正常2 正常系统初判“有效”绿色 / 正常
过慢3 过慢2 正常系统初判“有效”（仅提示）橙色提示
边界规则
  • 包含等号：y ≤ T05 和 y ≥ T95 都算命中；正好等于阈值也会被标记。
  • 过快优先：如果极端情况下同时满足过快和过慢（阈值配置异常），以过快为准。
  • 过慢不阻断：过慢只写入 duration_status=3，闸门三态仍是正常，不会判无效。
  • normal_v1 不会出现过慢：该版本只计算过快线，不计算高分位过慢线。
已知口径降级 percentile_v2 判定用的 y 优先读推定池 duration_answer_metric，保证与 T05 同源。 如果该行缺失（基线未构建/窗口外），系统会退回原始 Σx_q 参与比较。 原始值通常 ≥ 截尾值，因此可能偏向“不过快”，属于已知限制；正常情况下推定池应由 06:20 基线任务生成。
08

参照回退与门槛样本不够时，跟谁比

判一份卷是否异常，需要跟“同类分布”比。有的问卷样本多，有的样本少。 系统会按样本量从精确到粗放逐级回退；每一层都有准入门槛。

percentile_v2 的回退链

1
问卷 × 车系
n ≥ 200 稳定；50–199 为预热期。最精确，优先使用。问卷必须配置了车系。
2
问卷（不限车系）
n ≥ 200 稳定；50–199 为预热期。若上一层预热，会与本层做加权收缩。
3
类型（近 90 天）
n ≥ 200 稳定；50–199 为预热期。仅答卷级使用；题目级没有类型层。
4
品牌
n ≥ 300 稳定；50–299 为预热期。最后一级统计兜底，口径较粗。
5
种子值
运营/开发预填的经验 μ/σ。仅在统计层都不可用时兜底，可信度低，优先人工核对。
6
全空 / 不足 50
待定，不判正常。系统明确表示“无法可靠判定”，而不是默认放行。

加权收缩（预热期）

T = w · T当前组 + (1 − w) · T上级组
w = n / (n + 150) n=50 时 w≈0.25，几乎全信上级；n=150 时 w=0.5；n 接近 200 时几乎全信本组。目的是避免小样本阈值突变。

特殊兜底：如果整条链路上所有层都停留在预热期（没有稳定层），系统会取“最细的预热组”直接使用， 并在结论里保留“预热期”状态，让审核员知道这是预热期结论。

normal_v1 的回退链

层级样本门槛说明
问卷n ≥ 2000问卷自身样本
车系n ≥ 2000同品牌 + 同车系 + 同类型
类型n ≥ 2000同品牌 + 同类型
品牌n ≥ 300同品牌全量，门槛特意放宽
种子值—人工预填 μ/σ
全空 / 不足—正常放行（旧语义，回滚兼容）

normal_v1 的样本门槛明显更高；因此它更常回退到品牌层或种子值，也更容易受长尾数据影响。

参照层级 = 结论可信度

标签用的什么数据可信度审核建议
问卷层该问卷自己的历史样本高异常标记可直接采信
车系层同品牌 + 同车系 + 同类型样本较高基本可采信
类型层同品牌 + 同类型（跨车系）样本中参考，结合答案内容
品牌层同品牌全量样本，口径最粗中低谨慎，差异可能来自问卷难度
种子值人工预填的初始 μ/σ低仅参考，优先人工核对

多车系规则 问卷可以配置多个车系。聚合时会把样本复制到每个车系桶，但单卷判定只取问卷配置的第一个车系， 以保证“判定用的参照”和“聚合时第一个桶”一致。因此配置车系时，把最具代表性的车系放第一位。
题目级没有类型层 题目级按“问卷 × 题目”分组，不同问卷的题目 id 不同，类型维度上的“同题”没有业务含义， 所以题目级直接从问卷/车系回退到品牌层，不经过类型层。答卷级才使用类型层。

审核闸门时长不是第一优先级

每天 07:06 的系统初判，会先做设备风险与 NPS/NSS 规则，最后才看时长三态。 时长只是“附加条件”，不会覆盖前面的结论。

系统初判顺序

1
脏数据防御
push_task_user 关联缺失的孤儿卷直接跳过，不写审核记录。
2
填写中 / 有效期
未提交草稿且推送未满 21 天 → 暂不处理，等提交或过期后再判。
3
设备风险
设备风险异常 → 系统初判无条件无效，优先于时长与 NPS/NSS。
4
有效性配置完整性
未配置有效性题目、NPS 题目未配置、NSS 均未配置 → 保持待定，等业务配置补齐。
5
NPS/NSS 四条规则
命中任意一条 → 系统初判无效，时长不再参与。
6
时长三态闸门
1 异常 → 无效；2 正常 → 有效；0 待定 → 保持待定，次日再看。
时长三态系统初判说明
1 异常（过快）无效备注会写明 y、y门槛、参照层级，便于追溯
2 正常有效前提是 NPS/NSS 规则也未命中
0 待定待定时长数据未就绪/参照不足；次日系统初判会再次检查
关键区别 时长判定本身不修改 NPS/NSS 的符合性结论，也不修改 system_audit_status； 它只是在 NPS/NSS 未命中时，作为系统初判的最后一个条件参与决策。
待定会持续多久 06:40 的时长评估有幂等锚：同一份卷一旦冻结过时长，就不会每天重算。 因此“待定”卷在系统初判里会每天被重新检查，但时长值本身通常要等每周日的待定重判才会改变。 如果某个分组长期攒不够样本，这些卷可能长期待定。

冻结与追溯为什么昨天看是异常，今天不会变

06:40 评估时，系统会把“当时的结论 + 当时的阈值 + 当时的分位配置”一起冻结进审核记录。 之后无论样本怎么增长、参数怎么调，这条记录都不会自动回算。

冻结字段含义用途
y_duration该卷的推定答题时长（秒）列表/详情展示，CSV 转分钟
y_threshold判该卷时使用的低门槛（秒）解释“为什么判它过快”
threshold_low / highpercentile_v2 的低/高门槛快照（秒）低=过快线，高=过慢线
duration_percentile该卷在组内的经验分位（0–1）只对过快/过慢计算，用于解释
duration_status四态：待定/过快/正常/过慢页面展示明细
is_duration_anomaly三态闸门：待定/异常/正常SystemAudit 与列表明亮依赖
duration_ref_level命中的参照层级问卷层/车系层/类型层/品牌层/种子值/样本不足/无数据
baseline_sample_count该组基线样本量判断结论可信度
baseline_status稳定/预热/采集/未初始化判断结论可信度
baseline_source当前组/上级组/类型窗口/品牌/种子/无解释阈值来自哪里
duration_rule_version冻结时使用的规则版本历史追溯与回滚分析
duration_p_juan / p_ti冻结时生效的卷/题分位配置调参后仍能解释旧结论
duration_evaluated_at冻结时间幂等锚；判断是否已评估
冻结带来的三个结果
  1. 历史可追溯：审核员看到的是“当时为什么这么判”，不会被今天的新阈值误导。
  2. 调参只影响未来：修改 P_TI/P_JUAN 后，已冻结记录不变；新跑批的卷才用新参数。
  3. 重判只针对待定：每周重判默认只处理“待定”卷，并跳过已有人工审核结论的卷。

怎么判断报表数据健康

看样本量
n 是否足够
n 太小会触发回退；报表上的阈值可能不是该行自己的。
看状态
稳定 / 预热 / 采集
稳定期可直接采信；采集期结论应视为待定。
看离散度
σ 是否接近 0
σ≈0 说明样本同质化，正态口径下阈值会退化，容易误判。
看异常率
过快占比是否合理
默认 P_JUAN=5% 时，长期异常率应接近 5%（受并列值影响可能偏高）。
看待定率
是否大量积压
待定率高通常是基线不足/数据延迟，不是“都正常”。
看无数据
明细是否缺失
no_data 多说明数据组推送或 06:10 跑批异常。

分位门槛与调参P_TI / P_JUAN 到底改了什么

参数含义默认 / 范围调高 / 调低的影响
P_TI
题门槛		 单题“超长”的分位线。决定多少比例的单题会被清洗 95.0%
50.0% – 99.9%		 调高：超长题更少，更多单题保留原值 → 整卷时长更接近真实，但中途离开的干扰更难清洗。
调低：超长题更多，更多单题被压低 → 整卷时长普遍变短，y 门槛也会跟着降。
P_JUAN

0.1% – 50.0%		 调高：过快卷变多（审核压力增大，但漏网少）。

两套规则下参数的作用点不同

参数normal_v1percentile_v2
P_TI 决定单题“超时”线（μ题+k题σ题），超时题按 μ题/3 折算 决定单题 T95，超长题截尾到 T95
P_JUAN 决定 k卷，从而决定整卷 y 门槛 μ卷+k卷σ卷 决定低门槛 T05；高门槛 T95 取 1 − P_JUAN
调参只影响未来，不回算历史 修改后，已冻结的判定不变；只有下一轮 06:20 基线重建、06:40 评估的新卷才使用新参数。 想看效果，请观察“调参后新跑批的卷”，不要拿历史记录对比。

规则版本怎么切

  1. 确认基线表 duration_baseline 已有当前规则版本的数据（06:20 任务已跑通）。
  2. 在分位门槛配置中把 RULE_VERSION 改为 percentile_v2。
  3. 观察次日 06:40 之后的评估结果：过快/过慢/待定占比、参照层级分布。
  4. 如需回滚，把 RULE_VERSION 改回 normal_v1 即可。

注意：如果基线表还没有任何数据，即使配置成 percentile_v2，判定层也会自动回落 normal_v1， 避免“切了开关但没数据”导致全部待定。

固定项当前值 / 说明

加权收缩系数k = 150（w = n/(n+150)）

历史起算答卷 id44804（历史数据分界）

调参原则
  1. 一次只调一个参数，观察 3–5 天再决定下一步。
  2. 先看报表，确认异常率/待定率是否真的偏离预期，不要凭感觉调。
  3. 记录原因：为什么调、调后期望是什么，便于回溯。
  4. 默认值 95% / 5% 是统计常用分位，没有数据支持不要随意改。

重判与历史数据什么时候会变、什么时候不会变

每周待定重判

每周日 05:00 有一个“只重判待定”的任务，滚动覆盖最近 180 天：

  • 只处理 is_duration_anomaly=0（待定）的卷；
  • 默认跳过已有人工审核结论的卷，避免和人工审核打架；
  • 用当前基线重新判定，写回 y、阈值、四态、参照层级等；
  • 如果重判后从待定变成过快/正常，列表的红/绿状态会随之更新。

一份卷的状态什么时候会变

场景会变吗说明
样本每天增长不会已冻结记录不回算；新样本只影响新卷。
调整 P_TI / P_JUAN不会只影响未来跑批的卷；历史记录保留冻结值。
切换规则版本不会已冻结记录保留原规则版本；新卷按新规则。
每周待定重判可能只对待定卷；人工已审的默认跳过。
开发数据修复/重跑可能属于异常操作，需要记录原因。
用户重新提交可能产生新的答卷/新的评估，以最新一次为准。

历史数据的三点注意

  1. 旧记录 is_duration_anomaly=0 现在表示“待定”，不是“正常”；这是 v2.2.4 的语义变更。
  2. 旧记录没有分位快照（duration_p_juan/p_ti 为空），页面展示要做空值兜底。
  3. 旧记录可能没有规则版本，分析历史时不要假设它们都是 percentile_v2。
数据延迟怎么办 如果数据组推送延迟或 06:10 跑批失败，当天评估会落“无数据/待定”，不会默认正常。 等数据补齐后，靠每周待定重判补齐结论；紧急情况下可由开发手动触发重判。

异常场景 FAQ产品/运营最常问的问题

为什么有的卷没有时长标记，显示“待定”或空白？
常见原因有五种：① 无数据——数据组还没推该卷的答题明细，或 06:10 跑批没跑到；② 参照不足——各层样本都没到门槛，系统无法可靠判定；③ 阈值不可用——低门槛算不出来或 ≤0；④ 未评估——该卷还没进入 06:40 评估范围（例如未提交草稿且推送未满 21 天）；⑤ NPS/NSS 配置缺失——系统初判在配置检查阶段就保持待定。

待定不代表正常，需要正常人工审核。
为什么系统只标“过快”，从来不标“过慢”？
先确认当前规则版本：normal_v1 本身不计算过慢，只算过快线。 如果是 percentile_v2 仍看不到过慢，通常是因为过慢高分位阈值不可用： 当前高分位只从“问卷 × 车系”和“问卷”两层算，没有品牌兜底，样本不足 50 时算不出来。 另外，即使算出过慢，它也只提示、不入闸门，所以系统初判仍是有效。
为什么报表上的“有效答卷时长”和审核记录里的门槛不一样？
报表展示的是当前品牌层的实时门槛；审核记录里的是该卷冻结时、按它命中层级算出的门槛。 计算维度、时间点都不同，不能直接比较。审核时以记录里的冻结值为准；看趋势时看报表当前值。
为什么调了 P 卷门槛，历史卷的标记没变？
这是设计如此：判定结果冻结，调参只影响未来。修改后要等下一轮 06:20 基线重建、06:40 评估的新卷才会用新参数。 历史记录保留当时的分位快照与阈值，保证审核结论可追溯。
为什么同一份卷昨天是“待定”，今天变成“过快/正常”了？
正常情况下已冻结的卷不会每天重算。出现变化通常是：① 每周待定重判——它只处理待定卷；② 数据修复/重跑； ③ 用户重新提交。一般以最新一次冻结为准。如果大面积出现非待定卷被回算，反馈开发排查。
“答题时长”为什么和我直觉的答题时间对不上？
因为展示的是推定用时，不是墙钟时间。percentile_v2 会把超长题截到 T95，所以用户某道题离开很久时， 推定时长会比真实停留时间短。normal_v1 当前判定/展示使用原始 Σx_q， 单题清洗值 x_q*（μ/3）主要保留在明细层，不直接改变判定。 这个指标用于横向比较（跟同类比），不是用于还原真实耗时。
多车系问卷，判定用的是哪个车系的统计？
用问卷配置的第一个车系对应的统计桶。聚合时会把样本复制到每个配置车系，但单卷判定只取第一个， 以保证判定与聚合使用同一参照。配置车系时，把最具代表性的放第一位。
为什么车系维度报表的“有效时长”看起来像品牌层的数据？
这是当前实现的兜底：基线表按问卷拆分，无法给“车系 × 类型”一个跨问卷单值，所以车系行展示品牌层阈值。 它只用于观察，不是该车系的判定阈值。判定侧仍按问卷 × 车系 / 问卷层回退。
为什么 percentile_v2 下，问卷维度/类型维度的“有效答题时长”有时是空的？
因为题目级基线是按“每道题”存储的，没有“问卷汇总行”；报表按 question_id=0 查询时会取不到，页面按空展示。 这不影响判定侧。需要看单题阈值时，请以判定记录/基线明细为准，不要依赖报表该列。
报表上 n 为什么这么大？统计的到底是题还是卷？
报表有两套样本：题目级 n统计的是“单题时长”样本（同一问卷所有题的单题时长汇总），所以数值会很大； 答卷级 n统计的是“整卷”样本，一份卷计 1。看 KPI 时要区分 n题 和 n卷，不要混用。
为什么实际过快率会超过 5%？
经验分位使用 nearest-rank 取值。如果组内存在大量并列值（比如很多卷 y 都等于同一个秒数）， 取到第 k 个值后，所有等于该值的卷都会满足 y ≤ T05，覆盖率就会超过 5%。 这是经验 CDF 在跳变点的固有行为，不是算法错误；生产数据量大、分布连续时会更接近 5%。
为什么 ARIYA 品牌在时长报表/判定里看不到？
当前时长模块的品牌映射只覆盖“东风日产-日产 / 东风日产-启辰”（问卷 brand=1/2）。 其他品牌值不会进入品牌桶，也可能缺少品牌层基线。若需要覆盖 ARIYA，需开发扩展品牌映射。
