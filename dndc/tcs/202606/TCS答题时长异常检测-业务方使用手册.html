1这个功能是干什么的

一句话:自动标出"答得太快、可能是乱答"的答卷,帮你决定要不要发积分。

背景:积分答题环节里,有部分用户为了薅积分,会飞快地乱点一通提交问卷。这类答卷的特征是整体答题时间极短,明显低于正常用户。光看单份卷很难判断,但放到"同品牌/同车系所有答卷"里一比,异常短的就很扎眼。

这个功能就是替你做这个比较:系统会统计每个品牌/车系下所有答卷的答题时长分布,自动算出一个"正常下限"(称为有效答卷时长),凡是低于这个下限的答卷,就标记为"时长异常",在审核表单里高亮提醒你重点关注。

核心定位(很重要) 本功能只提供"可疑"信号,不自动处置。被标异常的卷不会自动拒发积分,正常卷也不会被改判。最终是否发放积分,始终由你(审核员)人工决定。系统只是帮你把"最值得怀疑的卷"排到前面、标红提醒,节省你逐份排查的时间。

它解决什么具体问题

痛点本功能怎么帮
乱答卷混在正常卷里,人工逐份看耗时异常卷自动标红 + 可"异常优先"排序,可疑的排最前
"多短算乱答"没有客观标准,审核口径不一用统计方法算出统一阈值(品牌/车系维度),全团队同一把尺
用户中途离开导致某题超长,拉高整卷时长,掩盖乱答单题层面先清洗(超长题按均值1/3折算),再判整卷,避免被离群值干扰
新问卷上线没历史数据,无法判定4 层参照回退 + 种子值兜底,新问卷也能用品牌层/种子值判

它不解决什么(边界)

  • 不判断"答案内容对不对"——只看答题快慢,不看答案本身质量(那是 NPS/NSS 规则的职责)。
  • 不抓"答得慢但乱答"的卷——只设下限(过快),不设上限(过慢)。故意磨蹭的乱答卷不在本功能范围。
  • 不自动拒发积分——标记仅供参考,处置权在你。

3.2"推定答题时长"是什么(为什么不是简单求和)

你看到的"推定答题时长"不是用户从打开到提交的墙钟时间,而是系统清洗后的一个可比指标。清洗逻辑:

推定时长的计算思路(不用记公式,理解逻辑即可)
  1. 逐题计时。系统按用户每次点击事件,算出每道题实际花了多少秒(支持来回修改累加)。
  2. 剔除超长单题。如果某道题耗时异常长(比如用户接了个电话没动),超过该品牌单题时长的 95 分位,就把它按均值的 1/3 折算,不让它拉高整卷时长。
  3. 求和得整卷时长。把折算后的各题时长加起来,就是"推定答题时长" $y$。

这样做的好处:即使用户某道题离开很久,也不会被当成"认真答了很久",乱答卷无处遁形。不同问卷的题数不同,但每份卷参与求和的题数恒定,时长跨卷可比。

为什么叫"推定" 因为单题层面做了 1/3 折算(不是用户真实停留时间),所以叫"推定"——它是用于判异常的可比指标,不等于用户真实答题时长。如果你想看真实耗时,这个值会偏小(超长题被压低了)。

3.3"参照层级"怎么看(判断结论可信度)

判一份卷是否异常,需要跟"同类的统计分布"比。但有些问卷样本多、有些样本少,系统会按样本量从精确到粗放逐级找参照。这个层级决定了你对该结论的信任程度。

参照层级(标签)用的什么数据可信度你的判断
问卷层该问卷自己的历史样本(≥2000份)高 最准异常标记可直接采信
车系层同品牌+同车系+同类型的样本较高基本可采信
类型层同品牌+同类型(跨车系)样本中参考,结合答案内容看
品牌层同品牌全量样本(最粗放)中低谨慎,差异可能源于问卷难度不同
种子值运营预填的初始 μ/σ(冷启动)低仅供参考,优先人工核对
样本不足4 层都达不到 2000 样本无系统未判异常,需完全人工
无数据明细数据还没跑出来无等明日跑批后再看,或人工核
审核要诀 看到异常标记时,先看参照层级:
• 问卷层/车系层标的异常 → 可信度高,重点怀疑;
• 品牌层/种子值标的异常 → 样本不够精确,异常可能是因为该问卷本身偏难/偏易,务必核对答案内容再定;
• 样本不足/无数据 → 系统没下结论,你正常审核即可,别因为没有异常标记就放松警惕。

3.4审核决策建议流程

拿到一份卷后,结合时长标记的推荐流程:

单份卷审核步骤(融合时长标记)
  1. 看异常标记。红标(异常)进入重点核查;绿标(正常)可走快通道。
  2. 看参照层级。问卷层/车系层 → 信任度高;品牌层/种子值 → 降一档信任;样本不足/无数据 → 无视标记,纯人工。
  3. 看推定时长 vs 有效答卷时长。(详情页会同时显示这卷的 $y$ 和当时冻结的 $y_{门槛}$。)差距越大越可疑。
  4. 核对答案内容。结合原有的 NPS/NSS 规则、答案文字质量,综合判断。时长只是参考之一,不是唯一依据。
  5. 下结论。发/不发积分的决策权在你;时长异常可作为"拒发"的理由之一,但不强制。
两个常见误用(务必避免) 误用一:看到异常标记就一律拒发 → 会误伤偏难问卷的正常用户(品牌层误判)。异常≠必定乱答。
误用二:看到绿标就闭眼过 → 绿标只代表时长正常,不代表答案没问题(可能是慢慢乱答)。正常≠必定合规。

4.2三个明细表(维度下钻)

KPI 下方有三个并列明细表,从粗到细看不同维度:

表每行是什么典型用途
问卷维度一行一个问卷(最细)查"某个问卷是不是异常特别多"——可能该问卷题目设计有问题
车系维度一行一个(品牌+车系+类型)组合查"哪个车系的用户答题偏快/偏慢",辅助问卷优化
类型维度一行一个(品牌+问卷类型)对比不同类型(销售/售后/车险...)的答题特征

每个明细表都有相同的列(n/μ/σ/有效时长),还多一列"关联问卷数"(车系/类型维度),反映该维度下有多少份 active 问卷在用这个统计桶。

报表数据怎么看健康度 健康的统计分布:样本量 n 足够(≥2000)、标准差 σ 适中(不要接近 0)。
• 若某问卷 n 很小(<2000)→ 它会回退到上层,报表上看到的阈值不是它自己的,要意识到;
• 若 σ卷 ≈ 0 → 说明该维度所有卷时长几乎一样,阈值会退化为均值,容易出现误判(见 FAQ Q5)。

5配置参数怎么调(产品/运营)

本功能有两个可调参数,在"分位门槛配置"页面。其他参数(替代系数 1/3、样本门槛 2000、单位)写死在代码,需走开发变更。

5.1两个门槛

参数含义默认取值范围调高/调低的后果
P题门槛
(P_TI)		 单题"超时"的分位线。决定多少比例的单题会被判超时并按 μ/3 折算 95.0% 50.0% – 99.9% 调高(如97%):超时题更少,更多单题保留原值 → 整卷时长更接近真实,但中途离开的干扰更难清洗
调低(如90%):超时题更多,更多单题被压低 → 整卷时长普遍变短,$y_{门槛}$ 也跟着降
P卷门槛
(P_JUAN)		 答卷"异常·过快"的分位线。决定多少比例的卷会被标异常 5.0% 0.1% – 50.0% 调高(如10%):异常卷变多(审核压力增大,但漏网少)
调低(如2%):异常卷变少(审核压力小,但可能漏判)

5.2调参的关键影响(必读)

调参只对未来生效,不回算历史 修改门槛后,只影响"今日凌晨跑批之后"新提交的答卷。已经审核过/已冻结判定的卷,标记不会变。

举例:周一把 P卷门槛从 5% 调到 10%,周一之前已标"正常"的卷不会重新变"异常";只有周二凌晨跑批后的新卷,才按 10% 判。这是设计上的"向后运用",保证审核结论可追溯。

所以调参的观察窗口是:调完后等次日跑批,看第二天起新卷的异常率变化,而不是看历史数据。

5.3调参原则建议

观察到的现象建议调整预期效果
异常卷标得太少,人工抽检发现还有漏网的乱答卷P卷门槛 调高(5%→8%或10%)异常率上升,更多可疑卷进审核视野
异常卷标得太多,审核员忙不过来,且大部分标异常的其实正常P卷门槛 调低(5%→3%或2%)异常率下降,聚焦最可疑的
某些卷因个别超长题(用户离开)被误判正常P题门槛 调低(95%→90%)更多超长题被折算,整卷时长更干净
正常的中等耗时题被误折算,导致整卷时长偏低P题门槛 调高(95%→97%)只折算极端超长题,保留更多真实时长
调参注意事项
  1. 一次只调一个参数,观察 3-5 天再决定下一步,避免多变量同时变无法归因。
  2. 默认值(95%/5%)是经过设计的,没有明确数据支持不要随便改。统计学上 95%/5% 是常用的"显著性"分位。
  3. 调参前先看报表:确认当前异常率是否真的偏离预期(太高/太低),而不是凭感觉。
  4. 改完记录原因:配置页会记修改人,建议在工单/文档同步说明"为什么调、调后期望",便于回溯。

7常见问题 FAQ

为什么有的卷没有异常标记(显示"—"或"空")?
三种情况:① 无数据——数据组还没推送该卷的答题明细,或跑批还没跑到,等次日再看;② 样本不足——4 层参照都不够 2000 份样本,系统无法可靠判定,主动放弃判;③ 该卷尚未触发评估——还没到提交审核环节。这三种都不代表"正常",你需要正常人工审核。
标了"异常"的卷,是不是就一定不能发积分?
不是。"时长异常"只代表"答得比同类快",是可疑信号而非定性结论。比如一份偏简单的问卷,正常用户也答得快,就会被误标。决策权在你:核对答案内容后,如果答案合理完整,该发还是发。建议把时长异常作为"拒发"的佐证之一,而不是唯一依据。
标了"正常"的卷,是不是就一定没问题?
不是。时长正常只代表"答得不快",但用户可以慢慢乱答(故意磨蹭)。本功能只抓"过快",不抓"过慢且乱答"。答案质量仍需结合 NPS/NSS 规则和人工核对。绿标=时长维度无异常,≠答案合规。
为什么同一份卷,昨天看是"异常",今天变成"正常"了?
正常情况下不会变。判定结论是冻结的(提交那一刻算定,落库后不回算)。如果变了,可能是:① 该卷重新提交了(产生新的判定);② 数据修复/重跑(罕见,需开发介入)。一般以最新一次冻结为准。若大面积出现回算,反馈给开发排查。
报表上某品牌"答卷标准差 σ卷"接近 0,正常吗?
不健康。σ卷≈0 意味着该品牌所有答卷时长几乎一样(可能是冷启动样本太少,或该问卷题目固定耗时)。此时"有效答卷时长"会退化为均值本身,等于均值的卷都会被判异常,容易误伤。遇到这种情况:等样本积累几天再看,或在种子值配置里补一个合理的 σ。
新问卷刚上线,异常标记都不准怎么办?
新问卷没有历史样本,系统会逐级回退:先试问卷层(空)→车系层(可能也不够)→类型层→品牌层→种子值。上线前可以让运营在"种子值配置"里预填一个合理的 μ/σ(参考同类型问卷),作为冷启动兜底。等该问卷自己积累够 2000 份样本后,会自动切到问卷层,判定变准。
我调整了 P卷门槛,为什么历史卷的标记没变?
这是设计如此(向后运用):调参只对"今日凌晨跑批之后"的新卷生效,已冻结的判定不回算。这样保证审核结论可追溯——你不能因为今天调了阈值,就让昨天已发积分的卷"变成异常"。要看新阈值效果,观察第二天起的新卷异常率。
"推定答题时长"和我直觉的"答题时间"对不上?
正常,因为推定时长做了清洗:单题超过 95 分位的部分被按均值 1/3 折算了。所以如果用户某道题离开很久,推定时长会比墙钟时间短不少。这是为了让乱答卷无处遁形(不被中途离开掩护)。你需要的是横向对比(跟同类比),不是纵向对比真实耗时。
多车系问卷的异常判定用的是哪个车系的统计?
用问卷配置的第一个车系对应的统计桶。问卷可以配多个车系,但判定时只取第一个(与聚合时多选展开的第一个桶对齐,保证判和聚用同一参照)。所以配置车系时,把最具代表性的车系放第一个。
异常率突然飙升/骤降,是 bug 吗?
先排查:① 是否刚调整过门槛参数(见 §5);② 是否有大促/活动导致样本结构变化(新用户多,答题特征不同);③ 某个问卷是否刚上线/下线影响品牌层样本;④ 数据组推送是否异常(明细缺失导致大量 no_data)。排除以上后再找开发。

8一句话速查表

看到...意思是...你该...
异常 + 问卷层答得太快,且参照很准重点怀疑,核对答案
异常 + 品牌层答得太快,但参照较粗参考,务必核对答案再定
正常时长没问题快通道,但仍看答案质量
无数据明细还没算出来等明天,或人工核
样本不足统计样本不够,系统没判无视标记,纯人工审核
调了门槛,历史没变设计如此(向后运用)看第二天起新卷的效果
σ卷≈0样本同质化,判定会失真等样本积累或补种子值
